# Scene tools for browser agents (WebMCP)

Status: implemented (Could), 2026-11-15; on kurviq.com for every Chrome with
the origin trial (token set 2026-11-15, expires 2027-03-30: renew by then)

## Why

Browser agents (an AI in the browser, e.g. Gemini in Chrome or an agent
extension) have no Kurviq connection: they click around the canvas, which is
slow and breaks easily. WebMCP (W3C Web Machine Learning CG draft,
`document.modelContext.registerTool`) lets a page offer tools to the browser's
agent. Kurviq's agent tools already run in the user's open tab, so the page
can offer exactly the tools of the MCP.

## How

- `scenes-plugin/src/webmcp/index.ts`: on the app page (not the renderer, not
  the public viewer), only where the browser has `document.modelContext`
  (`navigator.modelContext` before Chrome 150), the bridge is loaded.
  Elsewhere nothing is downloaded (the chunk is not in the offline precache).
- `bridge.ts`: the MCP's tools (`scenes-mcp/tools.mjs`, detached mode, no local
  files) with an in-memory MCP client (`scenes-mcp/inProcess.mjs`); each listed
  tool is registered with the browser (`webTool`, `adapter.ts`).
- "The scenes server" those tools ask is this tab (`localServerFetch`): the same
  commands the pairing WebSocket brings (`live.ts` `runAgentCommand`), no
  server in between. Kurviq's servers see nothing of it (data rule).
- Results are text: WebMCP hands a tool's result to the agent as a JSON string,
  so pictures (base64 PNGs) are named with their size, not inlined; a failed
  call answers `Error: …`. Hints: `readOnlyHint` from the MCP,
  `consequentialHint` for destructive tools (delete), `untrustedContentHint`
  for every tool that returns scene content (scenes may be shared).
- `read_me` returns the online reference with a page section: no upload
  address, images as data URL or inline SVG, big edits in parts
  (`kurviqPageReference`, `online/worker/skill.ts`). `create_view` (an inline
  chat widget) and `send_feedback` are not offered.
- `scenes-mcp/media.mjs` runs in the page with small shims (Vite plugin
  `scenesMcpInPage`): `node:buffer` → `buffer`, `node:crypto` → a synchronous
  SHA-1, `node:path` → `pathe`, `node:fs/promises` and `node:dns/promises` →
  nothing to read. Web images and icons can't be fetched from the page (its
  Content-Security-Policy): an error text says so.
- A note for agents that don't ask the browser for tools (they click and type,
  but read the page and can run JavaScript, e.g. Claude in Chrome): once the
  tools are registered, an off-screen paragraph (`agentNote.ts`, in the page's
  text and accessibility tree) says how to call them with
  `document.modelContext.getTools()` / `executeTool()`.
- Origin trial: with `KURVIQ_WEBMCP_TRIAL_TOKEN` (`.env`, GitHub secret) the
  app page gets `<meta http-equiv="origin-trial">`; without it, only Chrome
  with `chrome://flags/#enable-webmcp-testing` has WebMCP.

## Acceptance criteria

1. In Chrome with WebMCP (flag or trial), signed in on the app page:
   `document.modelContext.getTools()` lists the scene tools (`read_me`,
   `app_status`, `list_scenes`, `read_scene`, `edit_scene`, `save_scene`,
   `view_scene`, `delete_scene`, …), without `create_view` and `send_feedback`;
   the console says "19 scene tools offered to browser agents (WebMCP)".
2. `read_me` answers the page reference (no upload address, no `curl`).
3. `save_scene` makes a scene in Drive; `list_scenes` lists it; `read_scene`
   reads it with a revision; `edit_scene` adds an element, saved to Drive.
4. Pictures in results are named (`[picture: image/png, N KB, …]`), never
   inlined; `view_scene` the same.
5. Images from inline SVG and data URLs are added; a web address answers an
   error text and nothing is saved.
6. A failing call (unknown scene) answers `Error: …`, not a rejection; no page
   errors.
7. In a browser without WebMCP the bridge chunk is never requested.
8. Without sign-in the tools work on local-only scenes (as the MCP does).
9. Kurviq's server gets no request for a tool call (all in the tab).
10. With WebMCP the page's text has the note for agents (`#kurviq-agent-note`), naming `document.modelContext.getTools()`; without WebMCP there is no note.

Checked: unit tests `scenes-plugin/test/webmcp.test.ts` (adapter, SHA-1 against
Node's, the whole loop against a fake tab); e2e
`scenes-plugin/test/e2e/webmcp.mjs` (Chrome 157 with `--enable-features=WebMCP`,
real Worker + fake Google: criteria 1–6, 15 checks); criterion 7 checked by
hand (no bridge request without the flag). 8 and 9 follow from the design
(same command path as the pairing), not tested separately.

## Open

- Origin trial token (GitHub secret `KURVIQ_WEBMCP_TRIAL_TOKEN`, for
  `https://kurviq.com`) expires 2027-03-30: renew it at
  https://developer.chrome.com/origintrials/ and update the secret, or remove
  the trial when WebMCP ships without one.
- Brave has no WebMCP through the trial (origin trials are Chrome's); Claude in
  Chrome doesn't discover WebMCP tools by itself (2026-11-15), the note points
  it to them. Which browser agents call WebMCP tools today is unclear; try Chrome's
  "Model Context Tool Inspector" extension or DevTools → Application → WebMCP.
- Pictures: when the spec says how a result may carry images, pass them on.
- The API is a draft and changes (`navigator` → `document` in 2026): the
  adapter checks both; watch the Chrome release notes.
